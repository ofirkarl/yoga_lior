# יוגה עם ליאור

אפליקציית ווב לסטודיו "יוגה עם ליאור": הרשמה לשיעורים, ניהול כרטיסיות, ובהמשך תשלום דרך Grow.

## מטרות

1. **נגישות:** ממשק פשוט וברור בעברית, מימין לשמאל, לפי WCAG 2.1 AA.
2. **אבטחת מידע:** כל מתאמנת רואה רק את הנתונים שלה. פרטי אשראי לא נשמרים כאן. הצהרות בריאות פתוחות למנהלת בלבד.
3. **ווב קודם:** אפליקציית ווב שאפשר להתקין למסך הבית, ובהמשך לעטוף לחנויות.
4. **כניסה:** חשבון גוגל, או שם משתמש וסיסמה שליאור יוצרת ומאפסת.

## מבנה

| תיקייה | תוכן |
| --- | --- |
| `supabase/migrations` | סכמת בסיס הנתונים, כללי Row Level Security והפונקציות |
| `supabase/seed.sql` | המחירון והמערכת השבועית מהשאלון |
| `supabase/tests` | בדיקות אבטחה וחוקי הרשמה על Postgres מקומי |
| `src` | האפליקציה (React + TypeScript): כניסה, החלפת סיסמה, הצהרת בריאות, לוח שיעורים, השיעורים שלי, הכרטיסייה |
| `dev` | תצוגה מקדימה עם נתוני הדגמה, בלי Supabase |
| `supabase/functions/admin-users` | פונקציית שרת: ליאור יוצרת משתמשת עם שם משתמש וסיסמה זמנית, או מאפסת סיסמה |

## הרצת הבדיקות

דורש Postgres 16 מקומי:

```bash
supabase/tests/run.sh
```

הבדיקות מריצות את הסכמה על סביבה שמדמה את Supabase ובודקות, בין השאר, שמתאמנת לא רואה נתונים של אחרות, לא יכולה לשדרג את עצמה, לא יכולה ליצור לעצמה כרטיסייה, ושמועדי הביטול וההחזרים מחושבים נכון.

בדיקות הלוגיקה של פונקציית המשתמשות:

```bash
cd supabase/functions/admin-users && bun test
```

## הרצת האפליקציה

```bash
npm install
cp .env.example .env    # למלא את הכתובת והמפתח הציבורי של Supabase
npm run dev
```

תצוגה מקדימה עם נתוני הדגמה, בלי Supabase:

```bash
node dev/build-preview.mjs
npx serve dev/preview   # ואז לפתוח /?s=login, ?s=password, ?s=pending, ?s=health או ?s=main
```

## נגישות

- עברית מימין לשמאל, גופן בסיס 18px, כל אזור לחיצה בגובה 44px לפחות.
- תווית גלויה לכל שדה, הודעות שגיאה מקושרות לשדה ומוקראות לקורא מסך.
- ניווט מלא במקלדת, פוקוס בולט, קישור "דילוג לתוכן", וחלונות שמחזירים את הפוקוס כשנסגרים.
- כל זוגות הצבעים עומדים ב-WCAG AA (טקסט רגיל 5.9:1 לפחות).
- מצב שיעור לא מסומן רק בצבע, תמיד גם במילים.
- כיבוד הגדרת "הפחתת תנועה" של המכשיר.

## משתמשות בלי חשבון גוגל

ליאור יוצרת משתמשת במסך הניהול ומקבלת סיסמה זמנית להעביר לה. המשתמשת נכנסת עם שם המשתמש, וחייבת לבחור סיסמה חדשה לפני שהיא יכולה להירשם לשיעורים. באיפוס סיסמה המשתמשת מנותקת מכל המכשירים.

מאחורי הקלעים, Supabase דורש אימייל, אז כל שם משתמש נשמר כ-`username@users.yoga.invalid`. הדומיין `.invalid` שמור ולא מקבל דואר, והכתובת לא מוצגת בשום מקום.

## הקמה ב-Supabase

1. ליצור פרויקט חדש, באזור הקרוב לישראל (למשל Frankfurt).
2. להריץ את `supabase/migrations/0001_init.sql` ואחריו את `supabase/seed.sql`.
3. Authentication → Providers: להפעיל Google ו-Email. לכבות הרשמה עצמית עם אימייל וסיסמה, כדי שחשבונות סיסמה ייווצרו רק על ידי ליאור.
4. לפרוס את הפונקציה: `supabase functions deploy admin-users`, ולהגדיר `APP_ORIGIN` לכתובת האפליקציה.
5. אחרי שליאור נכנסת בפעם הראשונה עם גוגל, להפוך אותה למנהלת ב-SQL Editor:
   `update profiles set role = 'admin', status = 'active' where email = '<האימייל של ליאור>';`

## כללי אבטחה למפתחים

- אין כתיבה ישירה מהלקוח לטבלאות `bookings`, `entitlements` ו-`payments`. כל שינוי עובר דרך פונקציה.
- פונקציה חדשה סגורה כברירת מחדל. צריך לפתוח אותה במפורש עם `grant execute ... to authenticated`, ורק אם היא בודקת הרשאות בעצמה.
- מפתח `service_role` של Supabase נשמר רק בצד השרת (Edge Functions), אף פעם לא בקוד האפליקציה.
